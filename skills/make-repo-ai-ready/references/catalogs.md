# Generated catalogs (C4, C5, C6 table, C7)

Agents need facts that drift (fixture names, which job selects a marker, env vars). Hand-written lists of these
go stale silently, so each one is generated and guarded by a test that fails when the doc is stale.

## Pattern (one file per catalog, under the offline unit tests)
- The test file is both the generator and the guard: `python unit_tests/test_<x>_docs.py --write` rewrites the
  doc; run as a test it compares and fails with "run ... --write".
- Parse, never import: `ast` for Python (importing fixture modules pulls helpers that open DB clients), YAML for CI.
  The CI image may have no `git` binary: do not shell out to git.
- The doc starts with "Generated by <command>; do not edit by hand" and a "How to read it" paragraph.
- A generated block inside a hand-written doc sits between `<!-- <name>:begin (generated: <command>) -->` and
  `<!-- <name>:end -->`; the generator rewrites only that block.
- Register the test in the offline gate. AGENTS.md "keep the docs in sync": what change → which command → which
  doc, in the same commit.

## The catalogs
Names are suggestions; keep the repo's own if it has them.
| Catalog | Source | Columns |
|---|---|---|
| `docs/fixtures.md` | modules in root `pytest_plugins`, in order | name, scope, params, autouse, setup+teardown, what it gives (first docstring line), used by N tests |
| `docs/markers.md` | `pytest.ini` markers, lock plugin, CI selectors | marker, meaning, jobs that select it, lock, parallelism, "none: no job selects it" |
| jobs table in `docs/ci-jobs.md` | CI YAML (GitLab: incl. `include:` files; GitHub: `.github/workflows/*.yml` and called reusable workflows) | job, env, stage, concurrency group, selector, parallel, reruns, timeout, job retry |
| env table in README + `.env.example` | the declaring module (e.g. `config/run_settings.py`) | name, owner, default, required, description |

## Fixture docstrings
"What it gives" is blank without a docstring. Add a one-line docstring to every registered fixture in the same
ticket (one commit). State what the test receives and any side effect ("deletes ... after").

## Pitfalls
- Run generators with the repo's venv. In a worktree, an editable install points at the main checkout's `src`:
  `export PYTHONPATH=$PWD/src` or the generator documents the wrong tree.
- A new env var with a non-path owner fails an owner-exists check where the repo has one: owner is a repo path.
